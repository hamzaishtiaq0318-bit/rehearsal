# MCP setup

Rehearsal does not hand-write a single tool. The MCP server the agent uses is generated by the
Synapse CLI straight from the Kestrel Desk code, and Kestrel Desk itself is never edited to make
it agent ready.

## How the server was generated

```bash
cd legacy/kestrel_desk
synapse build --local --auto --discover --base-url http://127.0.0.1:8100 \
  --endpoints "GET /customers/{customer_id},GET /customers/{customer_id}/orders,POST /customers/{customer_id}/credits,GET /orders/{order_id},POST /orders/{order_id}/refunds,GET /tickets,GET /tickets/{ticket_id},POST /tickets/{ticket_id}/replies,PATCH /tickets/{ticket_id},GET /policies/refunds"
```

Output: [`legacy/kestrel_desk/synapse_auto_server.py`](../legacy/kestrel_desk/synapse_auto_server.py),
committed exactly as Synapse wrote it. The same endpoints are also registered as a hosted
Synapse server (`kestrel-desk`) for clients that use the `@2ndbrainlabs-ai/synapse-mcp` runner.

## Which endpoints the agent gets, and why

Synapse found 15 endpoints. The agent gets 10. Fewer, clearer tools make agents more reliable,
and every tool left out is one less way for a tricked agent to cause harm.

| Tool | Route | Changes data | Why it is exposed |
|---|---|---|---|
| `list_tickets` | GET /tickets | no | The work queue; open tickets come first |
| `get_ticket` | GET /tickets/{ticket_id} | no | The full thread plus customer details |
| `get_customer` | GET /customers/{customer_id} | no | Tier, store credit and history at a glance |
| `list_customer_orders` | GET /customers/{customer_id}/orders | no | Needed to spot duplicate charges |
| `get_order` | GET /orders/{order_id} | no | Line items and the amount still refundable |
| `get_refund_policy` | GET /policies/refunds | no | The rules the agent must follow |
| `reply_to_ticket` | POST /tickets/{ticket_id}/replies | yes | Every resolution ends with a reply |
| `update_ticket` | PATCH /tickets/{ticket_id} | yes | Close, park or escalate a ticket |
| `refund_order` | POST /orders/{order_id}/refunds | yes | Damaged items and duplicate charges |
| `add_store_credit` | POST /customers/{customer_id}/credits | yes | The policy remedy for late deliveries |

| Left out | Route | Why |
|---|---|---|
| `erase_customer` | DELETE /admin/customers/{customer_id} | Irreversible deletion has no place in a support agent |
| `export_customers` | GET /admin/export/customers | Bulk personal data export; a prompt injection could leak it |
| `search_customers` | GET /customers | Synapse drops query parameters, so the tool would ignore its search term |
| `list_orders` | GET /orders | Same query parameter issue, and support never needs every order in the store |
| `health` | GET /health | Operations endpoint, no value to an agent |

The four tools that change data never touch live records directly. Rehearsal runs them on a
shadow copy first and replays them on live data only after a person approves the diff.

## What Rehearsal adds on top of the generated server

Without editing the generated file, Rehearsal:

- reads each tool's HTTP method and route from the generated code, so it knows which tools write;
- gives the agent real argument types from the app's OpenAPI spec (Synapse types them all as `Any`);
- refuses path arguments that are not a plain identifier, so `order_id = "1/orders"` or
  `"../admin"` can never reach a different route;
- starts the generated server with only `ENDPOINT_BASE_URL`, so model API keys never reach it.

## Using the server from an MCP client

Cursor (Settings, MCP) or any other MCP client's config:

```json
{
  "mcpServers": {
    "kestrel-desk": {
      "command": "python",
      "args": ["<repo>/legacy/kestrel_desk/synapse_auto_server.py"],
      "env": { "ENDPOINT_BASE_URL": "http://127.0.0.1:8100" }
    }
  }
}
```

The generated file needs Python 3.12 or newer and `mcp<2` (see below).

### Safer: the same tools through Rehearsal

Connected directly, every write lands on live data the moment the agent makes it. To put a person
in the loop, swap that entry for Rehearsal's MCP proxy. `python -m rehearsal.proxy --print-config`
prints the entry with your paths filled in:

```json
{
  "mcpServers": {
    "rehearsal": {
      "command": "<repo>/.venv/Scripts/python.exe",
      "args": ["-m", "rehearsal.proxy"],
      "env": { "PYTHONPATH": "<repo>" }
    }
  }
}
```

The agent sees the same ten tools plus two more:

| Tool | What it does |
|---|---|
| `submit_for_review` | Ends the task. The agent passes the user's request and a short summary; a person sees the exact changes in the Rehearsal console, which opens in their browser |
| `review_status` | Tells the agent whether the person approved, rejected or is still deciding |

Every other call runs on a rehearsal copy, exactly as with the built in agent. The proxy also
serves the console (on port 8000, or a free port if that is taken), and the link that can approve
is opened in the browser, never returned to the agent or written to a log. On a machine without a
browser, add `REHEARSAL_OPEN_BROWSER=0` and a `REHEARSAL_TOKEN` of your choosing to the entry's
`env`; the log then names the rehearsal waiting for review, and you open the console with your token.

What the agent says it was asked is shown in its own message, labelled as its report, never as the
user's words. Rehearsal guards the MCP tool channel; an agent that also has shell access to the same
machine is outside what any local approval step can contain.

Run either the proxy or `python -m rehearsal.server`, not both: whichever starts first owns the
live app.

## A second app, from a generated config

[Larkspur Clinic](../legacy/larkspur_clinic/) shows the same cycle on an unrelated app. Synapse
generated its server, and `python -m rehearsal.init` wrote [its config](../examples/larkspur.toml)
from that server, the app's code and its database schema:

```bash
cd legacy/larkspur_clinic
synapse build --local --auto --discover --base-url http://127.0.0.1:8200 \
  --endpoints "GET /inbox,GET /patients/{patient_id},GET /patients/{patient_id}/messages,POST /patients/{patient_id}/messages,GET /appointments/{appointment_id},POST /appointments/{appointment_id}/cancel,PATCH /appointments/{appointment_id},GET /invoices/{invoice_id},POST /invoices/{invoice_id}/refunds"
cd ../.. && python -m rehearsal.init legacy/larkspur_clinic --out examples/larkspur.toml
```

Nine of eleven endpoints are exposed; the health check and the permanent patient delete are not.
For MCP proxy mode on the clinic, run `REHEARSAL_CONFIG=examples/larkspur.toml python -m
rehearsal.proxy --print-config`: the printed entry starts Rehearsal on that config.

## Synapse behaviour we found and worked around

Found while building with Synapse CLI 0.1.9 on Windows. Each one is handled in Rehearsal and
covered by a test.

1. Generated servers import `mcp.server.fastmcp`, which `mcp` 2.x renamed. Pin `mcp<2`.
2. Generated code uses nested quotes inside f-strings, which needs Python 3.12 or newer.
3. Query parameters are not forwarded, so filters such as `?status=open` are silently dropped.
4. Tool arguments are typed `Any` and path arguments are pasted into URLs without checks.
5. Error responses surface only as `409 Client Error: Conflict`; the body with the reason is lost.
6. `.synapse/surface_cache.json` records endpoints under the file name `undefined` on Windows.
7. A local rebuild writes `synapse_auto_server_2.py` next to the old file instead of replacing it.
