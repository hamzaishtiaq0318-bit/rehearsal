# Larkspur Clinic

The front desk app of a small physiotherapy clinic: patients, appointments, invoices, refunds and
messages. Plain FastAPI over SQLite.

It exists to prove one claim: Rehearsal protects **any** Synapse built app, not just the demo store.
Nothing in Rehearsal's code knows about this app. Its MCP server was generated by Synapse, and its
Rehearsal config was written by `rehearsal init`:

```bash
cd legacy/larkspur_clinic
synapse build --local --auto --discover --base-url http://127.0.0.1:8200 \
  --endpoints "GET /inbox,GET /patients/{patient_id},GET /patients/{patient_id}/messages,POST /patients/{patient_id}/messages,GET /appointments/{appointment_id},POST /appointments/{appointment_id}/cancel,PATCH /appointments/{appointment_id},GET /invoices/{invoice_id},POST /invoices/{invoice_id}/refunds"

cd ../..
python -m rehearsal.init legacy/larkspur_clinic --out examples/larkspur.toml
REHEARSAL_CONFIG=examples/larkspur.toml python -m rehearsal.server
```

Nine of the eleven endpoints are exposed. The health check and the permanent patient delete are
left out. One message in the inbox carries an injected "goodwill refunds" instruction, which the tests
in `tests/rehearsal/test_init.py` use to show Rehearsal catching it here too.

Seed a database by hand with `python seed.py path/to/larkspur.db`, and point the app at it with the
`LARKSPUR_DB` environment variable.
